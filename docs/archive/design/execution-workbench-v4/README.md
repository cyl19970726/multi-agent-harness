# Execution Workbench V4

```text
status: current targeted visual closure
owner_role: product-design + frontend-quality
canonical_for: post-Works visual contracts that supersede the V3 Team War Room evidence
```

V4 does not redesign every execution page at once. It contains narrow,
machine-readable visual contracts for product surfaces whose canonical data
model has changed after the broader V3 pass.

The first workstream is
[`team-war-room-works-closure-v1`](team-war-room-works-closure-v1/page-matrix.md).
It freezes the Shared Works default view at desktop `1440×1000`, tablet
`900×1180`, and mobile `390×844`, with a `320px` overflow guard. It also owns
the corresponding Activity hierarchy, Members capacity, responsive context,
keyboard, reduced-motion, and first-viewport acceptance.

## Truth boundary

- Expected images communicate hierarchy and density; they do not create
  runtime facts.
- Capacity values in implementation must derive from current MemberRuns and
  Works. In particular, no concurrency denominator or provider utilization
  percentage may be copied from a concept image without durable source data.
- Works own responsibility. Messages discuss Work. Wave context explains Host
  judgment. This visual contract must not restore Assignment Messages or make
  a Wave own the TeamRun.
- Raw browser runs live under `.visual-evidence/` and are reproducible; selected
  expected images, comparisons, overlays, specs, prompts and review decisions
  are durable repository artifacts.

V3 remains historical evidence for the pages it covered, but it is not the
acceptance source for this post-Works Team War Room closure.
