# Acceptance & Falsification · 验收与证伪纪律

Phase 3 自验与 Phase 4 验收的统一纪律。核心：**验收体系的设计目标是能被证伪，
不是能被打分。**

## 1. 判断权与词表（机械可执行）

- agent 自审/独立评审只产出：**逐元素落地证据 + 维度级偏差清单 + 诊断分数**。
- agent 报告出现 `PASS` / `符合设计` / `视觉达标` 字样且**无 Owner 批注引用** →
  机械打回，无需进一步阅读。
- agent 评审的合法结论词：`no-blocking-findings` / `findings(listed)`。
- 候选在 Owner 闸前的唯一合法状态名：`ready-for-owner`。
- **PASS 只有一个来源：Owner 对实际截图的明确批准。**

## 2. 双轨：硬不变量 vs 视觉诊断

- **硬不变量**（pass/fail，缺一不可）：产品语义、权限/隐私、动作安全、数据出处、
  旅程可达、无障碍阻塞、surface 覆盖。视觉再好不能抵一条硬失败。
- **视觉诊断**（分数/维度）：构图几何 25 / 信息层级密度 20 / 字体层级 15 /
  间距节奏 15 / 色彩材质 10 / 控件图标资产 10 / 状态交互动效 5。
  分数的唯一用途是**定位偏差在哪一层**，不构成验收结论；每个扣分点必须引用
  具体像素/区域与修法。

## 3. 分层闸（顺序不可跳）

1. 几何闸：壳/区域/比例/首视口/滚动归属 ── 不过则停，别谈样式细节
2. 主旅程闸：导航/实体/主动作/真实数据/权限隐私不变量
3. 覆盖闸：合同发现的全部 surface/状态/恢复路径
4. 视觉系统闸：字体/密度/间距/线面/控件/icon 一种语言
5. 响应式与状态闸：要求的视口变换 + loading/empty/stale/权限/错误/长内容
6. 机械验证闸：typecheck/lint/项目 browser-check 全绿 + 渲染证据（像素/computed）
7. Owner 闸：完整候选一次送交，非逐点小修逐次送审

## 4. 失效触发器（任一命中，旧评审/旧证据全作废）

- 实现 revision 变化（含前端/服务端构建号）
- 合同或 spec 版本变化
- 冻结参照图变化或 hash 变化
- 覆盖矩阵/验收维度/残余集合变化
- 代表性数据变化到足以改变已验收布局
- Owner 打回候选

窄 delta 想保留未受影响证据：必须由检查者写明"受影响面集合为何完整"并复测，
**禁止以"开发者说渲染没变"为由保留任何结论**。

## 5. 评审失效模式黑名单（命中即打回该评审）

- 只确认组件/数据存在、测试、console、无 overflow
- 复述实现者的完成叙事
- 没看全部阻塞截图就下结论
- 跨截图平均分数（99 和 91 不是 95）
- 只有局部挑刺，没有页面/模块级诊断
- 拿一个强帧代表整个模块
- 自称"独立评审"但与实现者共享同一上下文/叙事

## 6. 证据包（每次送 Owner 必须齐全）

- exact revision（40 位 SHA）+ 前后端构建号（如分离）+ spec 版本 + 参照 hash
- 路由/实体/代表性数据 id、视口、状态、捕获时间、环境、截图 hash
- fixture 证据与 real-data 证据分开标注
- 同尺度并排 montage（工具见 `measurement-toolbox.md` §3）

## 7. 规模分档（防止"全量流程太重→绕行→旧病复发"）

| 档 | 判据（可机械执行） | 免 | 不免 |
|---|---|---|---|
| 微调 | 不新增 surface/数据元素/组件，不动布局合同（如改色值/文案/间距微调） | 合同与 spec 全量编制、独立评审 | **三条铁律无豁免**：渲染证据、绑定 revision、Owner 批注 |
| 标准 | 触及现有 surface 的结构/状态/组件 | 无 | 五阶段全走 |
| 新模块 | 新 surface 或新 journey | 无 | 五阶段全走 + 合同先行 |

拿不准档级 = 标准档。**降档是判断，判断要留痕**（在交付物里写明所选档级与判据）。
